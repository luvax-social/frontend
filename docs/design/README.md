# Design Reference

> Record of work done on 2026-08-01. Not maintained; it is correct as of that date and is not updated as the code moves.

## What `Luvax.html` is

`Luvax.html` is a Claude Design HTML export.
It is a single self-contained file that bundles the entire Luvax interface prototype: the design tokens, every primitive, and every screen.

It is the pixel-perfect reference for this project.
Where the implemented interface and this file disagree, this file is correct.

Before this document existed the export lived only at `C:\Users\minhg\OneDrive\Desktop\Luvax.html`, outside both working trees and in no version control.
The conformance target for the whole project therefore depended on one file on one machine.
Committing it here removes that risk.

The file is 1,071,874 bytes and is byte-identical to the desktop original.

## Do not edit this file

The export is generated output, not source.
It is committed as a read-only reference.
Regenerating it from the design tool replaces it wholesale, so any local edit would be silently discarded.

## How the bundle is structured

The page carries a `<script type="__bundler/manifest">` element whose content is a JSON dictionary keyed by UUID.
Each entry has a `mime` field and a base64 `data` field.

The manifest holds 29 entries:

| Count | Type | Note |
|-------|------|------|
| 6 | `image/jpeg` | Photographic mock content |
| 3 | `application/javascript` | One is the application itself, 177 KB |
| 3 | `text/javascript` | React 19 production, React DOM production, and a design-tool runtime |
| 17 | `font/woff2` | The bundled webfonts |

Entries whose mime is `application/javascript` or `text/javascript` are gzip-compressed after base64 decoding.
The other types are not.

The three source chunks that matter:

| Chunk | Size | Contents |
|-------|------|----------|
| `ed9a0c12-...` | 176,988 B | Tokens, `LxIcon` and its icon tables, every primitive, every screen except messages, `App` |
| `9bffeb59-...` | 30,633 B | `lx-additions.js`: `LxMenu`, `ReportModal`, `CommentModal`, `LxHeaderSearch`, `ConfirmModal`, toast |
| `3b513cf1-...` | 44,507 B | `lx-messages.js`: `MessagesScreen`, `ConvRow`, `ConvOptionsMenu`, `MsgMenu` |

The three chunks load in sequence with polling guards.
`lx-additions` waits for `window.React && window.LxIcon`.
`lx-messages` waits for `window.React && window.LuvaxApp`.

## Extracting the chunks

Run from the frontend repository root.
This writes each decompressed JavaScript chunk to `/tmp/luvax-chunks/` for reading.

```python
import base64, gzip, json, pathlib, re

src = pathlib.Path('docs/design/Luvax.html').read_text(encoding='utf-8')
manifest = json.loads(
    re.search(r'<script type="__bundler/manifest">(.*?)</script>', src, re.S).group(1)
)

out_dir = pathlib.Path('/tmp/luvax-chunks')
out_dir.mkdir(parents=True, exist_ok=True)

for key, entry in manifest.items():
    if entry.get('mime') not in ('application/javascript', 'text/javascript'):
        continue
    source = gzip.decompress(base64.b64decode(entry['data']))
    (out_dir / f'{key}.js').write_bytes(source)
    print(f'{key}  {len(source):>7} B')
```

Expected output is six JavaScript chunks.
The three listed in the table above are the Luvax source; the other three are React, React DOM, and the design-tool runtime, and can be ignored.
